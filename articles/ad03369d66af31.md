## はじめに

WSL2環境でGoogle Antigravityを使ってブラウザテストを実行すると、テストが不安定に失敗するケースがよくあります。

この原因のひとつが、WSL2特有のNAT（Network Address Translation）環境です。WSL2はWindowsとは別の仮想マシンとして動作しており、ネットワーク的にも分離されています。そのため、WSL2内のプロセスとWindows側のブラウザが別マシンのように扱われることになり、ブラウザ連携がうまくいかないケースが発生します。

また、WSL2（NAT環境）におけるAntigravityのブラウザ連携問題については、以下の記事でも詳しく解説されています。
- [WSL2(NAT)環境でAntigravityのブラウザ連携を成功させる設定ガイド](https://blog.vemi.jp/entry/2025/12/30/153502)

こうした問題を回避しつつ、安定してAIによるブラウザテストを実現するために、本記事では **Playwright MCP** を使った構成を紹介します。

Google Antigravity（コーディングエージェント）に Playwright MCP を接続すると、**自然言語でブラウザテストができる**ようになります。「ブラウザで開いて確認して」「全機能をテストしてレポートを出して」と伝えるだけで、AIがページを開き、操作し、スクリーンショット付きレポートを自動生成してくれます。

セットアップは驚くほど簡単で、以下の3ステップ（実質コピペ）で完了します：

1. **MCP設定**: `mcp_config.json` に Playwright MCP を追加
2. **Workflow**: テスト手順をまとめた `.md` ファイルを作成
3. **Rules**: AIに Playwright MCP の存在を教えるルールを追加

## 動作環境

本記事の解説および動作検証は、以下の環境で行っています。

*   **動作ホスト**: Windows 11 ＋ WSL2 (Ubuntu: NAT環境)
    *   WSL2初期設定（`/etc/wsl.conf` の `systemd=true` や `appendWindowsPath=false`）が済んでいない方は、安定動作のためにあらかじめ [WSL2導入手順](https://zenn.dev/a143321/articles/46f164ebdacafb) を参照して設定を完了させておくことを強く推奨します。
*   **開発環境**: **Antigravity IDE Version 2.0.3+ (V2+)**
*   **Node.js**: v18以上 (パッケージ管理: npm / pnpm)
*   **ブラウザ操作**: Playwright MCP (ヘッドレス Chromium)

:::message alert
**⚠️ グローバルパスに関する注意**
公式ドキュメント等ではグローバルスコープの配置先として `~/.gemini/antigravity/`（例: `~/.gemini/antigravity/mcp_config.json`）が記載されている場合がありますが、本記事で動作検証を行っている **Antigravity IDE V2 / Version 2.0.3+** の環境では、グローバルな設定やカスタム Workflow アセットが `~/.gemini/config/` 配下に集約される仕様となっています。古いバージョンなど、お使いの環境の仕様に合わせて、適宜 `~/.gemini/antigravity/` 等にパスを読み替えて配置を行ってください。
:::

```
[ Windows ]
  └─ WSL2 (Ubuntu : NAT環境)
      └─ Antigravity（AIエージェント）
          └─ Playwright MCP（Node.jsベース）
              └─ ヘッドレス Chromium
```

## 構成と「安定する理由」

なぜ Playwright MCP なら設定不要でうまくいくのか？

通常、AIエージェントがブラウザを操作しようとすると、以下のどちらかに陥ってエラーになりがちです。

1. **NATの壁**: WSL2内からWindows側のChromeを操作しようとして、ネットワークが繋がらない
2. **GUIの壁**: WSL2内でブラウザを起動しようとして、Linuxのディスプレイ環境（X11/Wayland等）が連携できずにクラッシュする

Playwright MCP を導入すると、**「WSL2内にあらかじめ用意された超強力なヘッドレスChromium」をMCP経由で直接操作する**形になります。Windows側の環境へ通信しようとしてNATに弾かれることも、GUIを描画しようとしてWSLの壁にぶつかることもないため、ネットワーク構成をいじらなくても圧倒的に安定して稼働する、というのが最大のカラクリです。

## Playwright MCP とは

[Playwright MCP](https://github.com/microsoft/playwright-mcp) は、Microsoft が提供する MCP（Model Context Protocol）サーバーです。AIエージェントがブラウザを直接操作できるようにする仕組みで、以下のような機能を提供します。

- **ページナビゲーション**: URLを開く
- **スナップショット**: アクセシビリティツリーでページ構造を取得
- **スクリーンショット**: 画面キャプチャ
- **インタラクション**: クリック、テキスト入力、キーボード操作
- **コンソールログ**: エラー・警告の取得
- **レスポンシブテスト**: ビューポートのリサイズ

## セットアップ（3ステップ）

必要なものは **設定ファイル1つ + Workflow 2つ + Rule 1つ** だけです。

### 1. MCP設定（mcp_config.json）

Antigravity の MCP 設定に Playwright を追加します。

ファイル: `~/.gemini/config/mcp_config.json`

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": [
        "@playwright/mcp@latest"
      ]
    }
  }
}
```

初回実行時に Chromium が未インストールであれば、以下を実行します。

```bash
npx playwright install chrome
```

Playwright MCP は WSL 内部で Chromium を直接管理するため、冒頭で触れたNAT環境による連携エラーを確実に回避できます。

### 2. Workflow の設定

2つの Workflow を Global Workflow として登録します。

:::message
**💡 Workflow と Skill の配置スコープについて**
Antigravity では、カスタム手順（Workflow）や指示（Skill）をプロジェクト単体で有効化する「ワークスペーススコープ」と、PC全体で共通利用する「グローバルスコープ」の2種類の適用範囲が用意されています。

これらの概念やインストールディレクトリの詳細な比較については、以下の記事で徹底解説していますので、合わせてご参照ください。
👉 [Antigravity でプレゼン用シーケンス図を安定生成する — Workflow × Skill 設計パターン](/a143321/articles/antigravity-diagram-workflow-skill)
:::

Antigravity の Settings → Workflows → + Global から登録するか、以下のパスに直接ファイルを作成します。

#### `/browser-check` — さっと確認

ファイル: `~/.gemini/config/global_workflows/browser-check.md`

:::details browser-check.md のコードを見る

```markdown
---
description: Open and verify a local web app in the browser using Playwright MCP
---

# Browser Check (Playwright MCP)

Open a locally running web app with Playwright MCP to verify its display and behavior.

## Prerequisites

- Playwright MCP must be configured in mcp_config.json
- Chromium must be installed (run npx playwright install chrome if not)

## Steps

// turbo
1. Start a local server in the target project directory:
   cd <project-directory> && python3 -m http.server 8080

2. Open and verify the page with Playwright MCP:
   - Use mcp_playwright_browser_navigate to open http://localhost:8080
   - Use mcp_playwright_browser_snapshot to check page structure
   - Use mcp_playwright_browser_console_messages to check for errors
   - Use mcp_playwright_browser_take_screenshot to capture the current state
   - Click, type, or interact with elements as needed to verify behavior

## Notes

- Screenshot save location depends on the Playwright MCP working directory
- If an issue is found, take a screenshot at that point and report it
```

:::

#### `/browser-test` — テスト＋レポート

ファイル: `~/.gemini/config/global_workflows/browser-test.md`

:::details browser-test.md のコードを見る

```markdown
---
description: Run browser tests on a local web app using Playwright MCP and generate a report with screenshots
---

# Browser Test with Report (Playwright MCP)

Run a comprehensive browser test on a locally running web app using Playwright MCP.
Generate a test report with embedded screenshots as an artifact.

## Prerequisites

- Playwright MCP must be configured in mcp_config.json
- Chromium must be installed (run npx playwright install chrome if not)

## Steps

// turbo
1. Start a local server in the target project directory:
   cd <project-directory> && python3 -m http.server 8080

2. Open the page and run baseline checks:
   - Use mcp_playwright_browser_navigate to open http://localhost:8080
   - Use mcp_playwright_browser_console_messages to check for errors
   - Use mcp_playwright_browser_snapshot to verify page structure
   - Use mcp_playwright_browser_take_screenshot to capture the full page (fullPage: true)

3. Test interactive features:
   - Click buttons, links, and interactive elements
   - Test keyboard navigation if applicable
   - Take a screenshot after each significant interaction
   - Verify expected state changes via snapshot

4. Test responsive layout:
   - Use mcp_playwright_browser_resize to set mobile size (375 x 812)
   - Take a screenshot of the mobile view
   - Test key interactions at mobile size
   - Restore desktop size (1280 x 720) when done

5. Generate test report:
   - Copy all screenshots to the artifact directory
   - Create a Markdown artifact with:
     - Test result summary table (PASS/FAIL for each item)
     - Detailed findings with embedded screenshots
     - Any errors or warnings found
     - Improvement suggestions if applicable

## Notes

- Screenshot save location depends on the Playwright MCP working directory. Use find command to locate them before copying.
- Always take a screenshot when an error is found and embed it in the report.
- Do not stop the local server after testing (user will decide).
```

:::

:::message
`// turbo` は Antigravity の Workflow 用アノテーションです。直下のステップでシェルコマンドを実行する際に、ユーザー承認なしで自動実行（`SafeToAutoRun: true`）します。サーバー起動のような安全なコマンドに付けると作業がスムーズになります。
:::

### 3. Rule の設定

AIが Playwright MCP の存在を常に認識できるよう、Global Rule を追加します。

ファイル: `~/.gemini/GEMINI.md`（または Antigravity Settings → Rules から登録）

```markdown
## Browser Testing

- Playwright MCP is available for browser interaction and testing.
- When verifying a web app, use the /browser-check workflow.
- When running a full test with report, use the /browser-test workflow.
- Use mcp_playwright_browser_* tools to navigate, snapshot, screenshot, click, and interact with pages.
- Always check console errors and take screenshots when issues are found.
```

この Rule があることで、新しい会話でも AI が Playwright MCP を自動的に認識し、Webアプリの動作確認やテストに活用します。

## 実際に使ってみる

### テスト実行

フォトギャラリーアプリ（gallery3）を対象にテストを実行しました。

Antigravity に対して以下の一言を伝えるだけです。

> gallery3 をローカルで `/browser-test` してレポートを出して。

AIは以下を自動で実行します。

1. ローカルサーバーの起動
2. ブラウザでページを開く
3. 全機能のテスト（クリック、キーボード操作等）
4. レスポンシブ表示のテスト
5. スクリーンショット付きレポートの生成

## まとめ

Playwright MCP × Antigravity の組み合わせにより、**自然言語でブラウザテストを記述・実行・レポート生成する環境**がたった3ステップで構築できました。

| 必要なもの | 用途 |
|:--|:--|
| `mcp_config.json` | Playwright MCP の接続設定 |
| `/browser-check` | さっと確認用 Workflow |
| `/browser-test` | フルテスト＋レポート用 Workflow |

## browser_subagentを使用する方法

Antigravity には `browser_subagent` というブラウザ操作ツールもあります。CDP（Chrome DevTools Protocol）モードで Chrome を起動し、WSL2 側から接続する方式です。
